# M2 report: mail actions, menus, reader depth, search, unified inbox, plugins

**Status: awaiting HAND TEST 2** (and HAND TEST 1 of M1 before it). Branch `m2` (not merged to `main`, not tagged). Plan:
[M2-plan.md](M2-plan.md); scope and exit: [PORT-PLAN.md](../PORT-PLAN.md) §5 "M2". Verified on 2026-11-17 by the M2 verify stage on
the merged branch: stage F and the five streams (`actions`, `menus`, `reader`, `search`, `unified`), each reviewed and merged (history:
`git log --first-parent m2`).

**In one paragraph.** Windows and Linux are both green: Windows 1430 tests, 0 failed, 4 skipped; Linux 1426 tests, 0 failed,
6 skipped. Every M2 Rust test is ported: 89 rows, plus 14 early rows of M4 and M6. All 36 M2 plugin hooks have call sites.
trace-diff matches for M1's open, switch and push, and for the new delete_undo and move traces. Cold start is unchanged
(first frame 310 to 322 ms).

This is the first milestone where the frame gates could be measured. WGC delivered real frames, and the context menu, the dialog,
the palette and delete/undo show 0 BLANK and 0 FLASH in both styles and both themes.

Three things keep M2 from its exit:
1. **Many interaction rows are still open.** 70 of the 141 M2 interaction rows, plus 19 M1 rows carried over, are still `todo`.
   Most are views the streams did not build: the account popover, the hover strip states, the sidebar "+", tag management, the
   reader toolbar and More menu, and others.
2. **No live writes ran.** Decision M2-Q2 is still a proposal and the `.local` lists do not exist, so nothing was written to
   `<test-account>`. That includes the cleanup of the Rust leftovers.
3. **Real input is untested.** Real pointer and keyboard paths are hand tests.

## 5. Open issues (also in the Fable log)

1. **Interaction rows.** 70 M2 rows and 19 carried M1 rows are `todo` (§2). This is the exit gap.
2. **No live writes.** Nothing was written on `<test-account>`: M2-Q2 is not approved and the `.local` lists are missing.
3. **Unified with real logins.** With two real logins, only one account's rows appeared (§4). The sidebar Inbox row stays highlighted while All inboxes shows (unified review request: clear the folder selection). There is no unified right-click menu, no per-account rows and no shared section.
4. **Reader entry points missing.** The reader's More button is disabled and there is no MENU-READER or MENU-ATT. As a result:
   - the quick rules can be reached only from MENU-MAIL and the folder Rules flyout;
   - view source, forward as attachment and Save to Files have no UI;
   - `IAvatarService` and `IAttachmentSaver` have no UI consumer.
5. **Snippet marks.** They are not drawn in the rows (I-232, L-050).
6. **Import and export entry points.** There is no folder-menu entry, no Ctrl+O and no platform file picker (I-065, I-287). Only automation's queued picks work.
7. **Feel left over.**
   - Bento dialog open: one frame of 27 to 29 ms in 2 of 9 runs.
   - One 34.8 ms gap during a 500-message import.
   - `search_results` and `chip_remove` are unmeasured (script).
   - `import-sim` holds the automation connection until the import ends.
8. **Linux.**
   - The first X11 capture after a message opened showed the body as a white block in the dark theme. This is a possible WebKitGTK white flash before the first paint.
   - 4 X11 frames were seen in the first 0.5 s of the idle probe.
   - A Linux build still restores `Barbican.Platform.Windows` (stage F request).
   - The Secret Service store has never run against a real service.
   - The VM has no Calendar or Uno real-input path.
9. **MimeKit and DnsClient AOT and trim are unproven.** No trimmed publish was made. The plugin payload JSON uses reflection (trim warnings suppressed).
10. **Known parity choices to confirm** (Fable log):
    - writes are never retried, and a failed chunk stops the rest;
    - select all in folder is capped at 10 000;
    - undo of `trash-and-read` leaves the messages read;
    - Escape in a flyout closes the whole menu;
    - Sieve save has no `ifInState`;
    - trusted senders are keyed on the From address only;
    - R2-07 with Stalwart's `add_received` off.
11. **Tooling fixed in this stage.** `tools/linux.ps1` used Git's MSYS ssh when started from Git Bash. It ran only the remote echo and looked finished, which is why the streams saw "no test result". It now calls Windows OpenSSH.

Fixed by this stage:
