# Accessibility quick panel evidence and remaining work

M6 accessibility quick panel. The app command is shared by the existing Alt+Shift+A route, the palette and the optional rail button. It opens a custom in-window dialog. Quick choices use the shared ISettingValues writer; the seven reference presets write their individual preference values and offer undo. Errors stop preset writes and remain visible; a partial preset can be undone. The control named Off for focus outline retains a minimum native keyboard outline intentionally, to keep keyboard focus discoverable.

The live common metrics currently cover quick-panel text/targets, the rail and compose button, and StyleState-bound list, folder, tag, reader subject and sender text. They do not implement global text scaling: static-sized XAML remains in Accounts/AccountPopoverView, Actions/SelectionBarView and ToastHostView, Calendar/AgendaView and Tasks/TasksListView, Compose/ComposerView, Contacts/ContactsListView, Context/ContextView, Dialogs/DialogHostView, Glance/GlanceTilesView, List/MessageListView (some metadata), Palette/PaletteView, Rail/RailView (some glyphs), Reader/ReaderView (some metadata), Search/SearchBoxView, Shortcuts/ShortcutSheetView, SignIn/SignInView and Unified/UnifiedSectionView. Code-created views and WebView body require separate audit as well. M10 must complete these consumers with responsive layout and accessibility validation; do not describe this checkpoint as global scaling.

Reference preset effects without established native consumers include `largeCursor` (reference app/accessibility.css:461-471 applies CSS cursor images; Windows system cursor settings must not be changed globally), `nativeScrollbars` (reference app/globals.css:297-324 switches custom web scrollbars off; native WinUI scrollbars are already system controls, so a wider native analogue still needs design), and `pauseAnimatedImages` (reference hooks/use-mail-reading.ts:103 and components/email/email-viewer.tsx:4011 freeze message images with per-image controls; the WebView implementation needs its own safe equivalent). Other preset members require an individual call-site audit; persistence alone is not proof of effect. The font stage bundles native Atkinson Next, Lexend and OpenDyslexic files and their OFL notices; see `src/Barbican.App/Assets/Fonts/README.md`. Windows hidden samples visibly exercised each family. Missing-glyph fallback, dynamic weight mapping and Uno/Skia rendering remain to be verified.

Hidden sample verification: the Automation Windows build succeeded. The existing shortcut opened AccessibilityQuickRequest; the optional rail button opened the same request; sample contrast persisted; the Motion preset wrote reduceMotion and Undo restored it; the full-settings action opened the Accessibility page; popup guard reported only the constrained dialog and zero popups after closing. Nonuniform normal and 1.5x sample captures were visually inspected. The hidden non-activated window did not report a focused XAML element and its simulated Tab was unhandled: initial focus, focus trapping/restoration and visible keyboard focus therefore still require a focus-capable isolated test. The shared host now attempts to focus the first custom control instead of its hidden OK button, but that is not proof of successful focus.

The intent is to preserve shared brushes, native controls and immediate reduced-motion behavior. Generated theme token XAML is not changed. Linux/Uno execution, all individual preset effects and extreme-scale layout are not verified here.
