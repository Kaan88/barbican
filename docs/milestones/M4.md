## What shipped

- **Data (cal-data).** Calendar store (Calendar/get, CalendarEvent query and get in chunks, shared accounts, namespaced ids), live updates through the
  generic push and /changes engine, the recurrence engine and time zones (NodaTime; Ical.Net is the differential oracle only), occurrences, reminders
  (rules, a scheduler over every signed-in login on `TimeProvider`, state store, missed list, popup view model), `CalendarSettings`, the FakeJmap calendar arms.
- **Editing (cal-edit).** Event and task writes by scope (single, all, occurrence, following), drag move with rollback, guests and organiser rules,
  invitations (RSVP, add, counter, cancel) and the reader banner actions, .ics import and export, webcal subscriptions (LAN and localhost blocked, plain
  http warned), birthdays, guest search, find a time and availability.
- **Views (cal-views).** The Calendar app in the shell, toolbar, sidebar (mini month, calendar list), Day, Week, Month and Agenda, the all-day strip cap,
  hover preview, drag move, resize and create with rollback, search results, in-window print preview.
- **UI (cal-ui).** Event editor, recurrence editor, alerts, guests, availability and find a time, quick create, scope and discard dialogs, task editor,
  calendar and subscription dialogs, import dialog, 40 calendar commands, 6 menu providers, palette entries and shortcuts, hidden commands
  `cal-editor-open/set/save`, `cal-task-add`.
- **Integration (this pass).** Tasks list view and the capped sidebar task list (the two slots), reminder stack and missed-reminders dialog (one shell
  overlay), the editor card host over the calendar grid, the mini month's day pick feeds the Tasks view, a timer for the subscription refresh interval
  and the start of the reminder scheduler (nothing started it before), the `timeZone` setting in the grid and the editors' zone maths, one calendar member in
  `MenuContext`, the two same-named `ICalendarSource` seams told apart (`IEditorSource`), a sample-data editor and tasks backend for hidden runs,
  `cal-reminder`. Checked and fine: the UI awaits of the writer, the invitation actions and the gestures all use `ConfigureAwait(true)` (the one
  wrong-thread bug cal-views found in `CalendarGestures.WriteAsync` was already fixed); the reminder popup now raises `Missed` through the dispatcher.
- Screens (sample data only) in [M4-screens/](M4-screens/): `cal-week`, `cal-day`, `cal-month`, `cal-agenda`, `cal-agenda-bulk` (cal-views), and from the
  integration run `cal-editor`, `cal-week-after-save`, `cal-tasks`, `cal-reminder`.

## What is unproven

- **Live runs.** The plan's live checks on `<test-account>` and `<readonly-account>` (L-012 RSVP, L-020..L-025, L-027 thousands of tasks, L-028, L-029,
  L-030 cleanup list) were not run in this pass; everything ran on FakeJmap and the in-memory sample source. Run them before M5 relies on the calendar.
- **Needs a human.** Drag with a real pointer, a reminder notification on the real desktop (the OS notification and the sound are M7's), printing on paper
  (the print model is tested, the OS print path is built but never run), the real look of the cards at other window sizes.
- **Server support.** Find a time and availability need `urn:ietf:params:jmap:principals:availability` (D-M4-13); whether the test server offers it is not
  recorded. The Calendar rail entry needs `urn:ietf:params:jmap:calendars`.
- **Time zone setting.** The grid and the zone conversions honour `timeZone`; the zone a new event or task is created in (`CalendarJson.LocalZoneId`, a
  static helper) still comes from the machine (D-M4-I04). Tasks on the grid are day markers and are not converted.
- **Sample-data editor.** The sample backend writes whole titles, times and progress only; guests, recurrence expansion of a created series and
  scope questions are covered by the unit tests, not by the hidden run.
- **Subscription refresh** is proven by a fake-clock test (`CalendarSubscriptionRefresherTests`), not against a real feed.
