# Changelog

Each release of Barbican is listed here, newest first. The section for a version is the text of its
GitHub release, its first line is the note Hub shows, and a release is refused when the version
has no section here. Before tagging, rename "Unreleased" to the version and the date, for
example "## 0.1.0 — 2026-12-01", and start a new "Unreleased" above it.

## Unreleased

- Contacts: saving a contact no longer loses the other units of its organisation. Editing the Department field changes only the first unit of the first organisation; its other units, the other organisations and properties Barbican does not show are kept, and emptying the field removes only that first unit.
- Contacts: a birthday on 29 February now counts down to 1 March in years that have no 29 February (it used to point at a date in the past), and a date typed in the contact form must be a real calendar day (31 April and 29 February 2023 are refused; 29 February without a year is fine).
- Contacts: importing a vCard file from someone else is bounded. A file over 16 million characters is refused (it is not read into memory), at most 10 000 contacts are read per import, a line over 1 million characters is skipped, a card keeps at most 5 000 property lines and 500 entries of each kind, a card begun inside another card starts the card over, and a photo above 8 MiB or whose text is not base64 is left out while its contact is kept. The import summary says what was left out.
- Contacts: a picked or stored picture above 8 MiB, or above 40 million pixels by the size in its header, is refused before it is decoded, so a small file that claims a giant picture cannot make Barbican use gigabytes of memory.
- Contacts: an exported vCard can no longer carry a line break inside a value (addresses, numbers and links were written as they were), so a contact cannot forge extra properties or end its own card in an export. Media types in exports are checked, and the file name offered for one exported contact never ends in a dot, is never a Windows device name and is at most 80 characters.

## 0.1.1 — 2026-11-24

- The window reopens where you left it: its size, position and whether it was maximised are remembered on this computer (not synced with your settings). When the monitor it was on is gone or the screen changed so the window would be off screen, Barbican opens at the default size and place instead.
- Sign-in safety: redirects from the server are followed by hand, to the same address only and never from https to http, at most 5 hops (session discovery, API calls, downloads, uploads, push, the admin key and the AI key). A server that redirects elsewhere is refused with the address named instead of ending in "wrong password". A sign-in the server turns down is tried once: no reconnect loop, no refresh loop, and you are told once. Two Barbican windows on one profile no longer lose a rotated sign-in token, and closing one no longer writes its older copy over a newer one.
- Credentials: secrets are kept per profile (`BARBICAN_PROFILE`; the default profile is yours), in the Windows Credential Manager with local-machine persistence (not roaming). Your 0.1.0 sign-in moves over by itself the first time 0.1.1 starts; going back to 0.1.0 afterwards asks you to sign in again. Test and automation runs (`BARBICAN_AUTOMATION=1`) never use your profile: without a profile they get `auto-<port>`, with their own folder and sign-in.
- Clicking a new-mail notification now shows the folder the message is in, not only the message: the folder is selected in the list on the left (and unfolded when it sits inside a collapsed folder), its messages are listed and the message is highlighted. Before, the folder that was open before stayed selected, so the message and the folder disagreed. A message that was filed to another folder since the notification is found where it is now, a deleted one only says it is gone, a search or tag is cleared so the message is in the list, and the "All inboxes" view gives way to the message's own folder (as Bulwark does). Notifications for several new messages select the Inbox of the account that got them the same way. A notification of another signed-in account switches to that account first (as Bulwark does) and then opens the message in its folder (or the Inbox); accounts are matched by the login you signed in with, also when the server's own name for the account differs from it. If you open another folder or message while the message is being looked up on the server, you stay where you are. A search that already lists the message is kept. The Archive, Mark as read and Delete buttons on a notification of another account now say that it belongs to another account instead of doing nothing.
- Fixed: switching on Gravatar photos (or sender favicons) crashed Barbican at once, and then on every start. If a start does crash, the next one runs with sender pictures off and says so.
- Signing out removes the account's data from this computer: its caches, trusted senders, the mail view's cookies and storage, plugin data and the saved sign-in. Files that are still in use are removed at the next start.
- Signing out is per profile: a profile keeps its own mail view data, files opened from mail and print file (`%TEMP%\Barbican-<profile>`, the default profile keeps `%TEMP%\Barbican`), so signing out in one profile never deletes another profile's data. The login form no longer keeps the password or 2FA code after signing in or out, and a sign-out says so when the saved sign-in could not be removed from the Credential Manager. A start that crashed is only noticed when the first list did not get drawn (not after a fixed 8 seconds), and a second Barbican window is no longer put into safe mode by the first one starting, nor does closing it clear the first one's check. Only the default profile checks for and installs updates.

## 0.1.0 — 2026-11-23

- First installable build: a per-user Windows installer (Inno Setup, Barbican-Setup-<version>.exe), next to the portable zip, with a Start menu shortcut, an optional desktop shortcut and upgrade in place. It needs no administrator rights, and it never ends a running Barbican (including one only in the tray): it asks it to close, waits up to 30 seconds, and when it is still there it asks you to close Barbican first instead of installing, so an open draft is not lost. Uninstalling also removes the registry entries the app wrote for itself (start at login, the mailto: registration).
- barbican.exe carries a Windows version resource and the application icon, so Explorer and Hub show the right version.
- Updates: an install made with the new installer can update itself like the MSI one does (signed manifest, SHA-256 check, installed only when you say so).
- Mail, calendar and contacts in the Bento × Nordic design, with a native rich-text composer (spelling, tables, images), a unified inbox, schedule send, invitations, filters and Sieve extras, a command palette and search, drag and drop, and .eml/.mbox import.
- Settings include an accessibility page; the app can start in the tray, close to the tray and show an unread badge.
