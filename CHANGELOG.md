# Changelog

Each release of Barbican is listed here, newest first. The section for a version is the text of its
GitHub release, its first line is the note Hub shows, and a release is refused when the version
has no section here. Before tagging, rename "Unreleased" to the version and the date, for
example "## 0.1.0 — 2026-12-01", and start a new "Unreleased" above it.

## Unreleased

- Notifications and settings: Settings > Notifications > Tone now offers Bulwark's five tones (Beep, Cheerful, Involved, Swift Gesture, Relax), kept under Bulwark's own `notificationSoundChoice`, and new-mail and calendar notifications play the chosen one with the closest sound Windows has built in (Beep = Default, Cheerful = IM, Involved = Mail, Swift Gesture = SMS, Relax = Reminder; Linux plays the nearest freedesktop sound). There is no speaker button and no preview yet, because a notification is the only way this build can play a sound: nothing plays when you pick a tone, the next notification does. Settings > About > Fix problems now has Bulwark's "Refresh cached data": press Refresh twice and it deletes the sender pictures kept on disk, forgets the pictures, verified-brand (BIMI) answers and opened message bodies held in memory, then loads folders, the list, contacts and calendars again from the server. Settings, sign-ins, drafts and the outbox, plugins and what they stored, other profiles, the app lock and the mail view's WebView profile are left alone.
- Plugins: API 2 plugins now run. Switching on an installed API 2 plugin loads it (its own manifest must match the package's) and gives it Barbican's core host calls: its own storage (per plugin and per signed-in account, 1 MB each, removed when you uninstall the plugin or sign that account out), its settings, which you set under its switch in Settings > Add-ons, notices and OK/Cancel dialogs that Barbican draws with plain text that names the plugin, web requests only to the https sites you accepted for it (never to an IP address; a host inside your network only when you accepted it as such; every redirect is checked again; no cookies or Barbican sign-in go with them), and who is signed in (address, name and server, never a password or token) when it asked to see your accounts. Every call is checked against what you accepted and refused otherwise; a plugin that makes too many calls is slowed down and, if it keeps on, switched off until Barbican restarts. API 2 plugins are not called from mail, calendar or other screens yet.
- Files and downloads: a folder (its Download button or "Download as zip" in its menu), or everything in the folder on screen ("Download all as zip" in the folder menu), now downloads as one .zip with the same folders inside, empty ones included; it is written to disk as the files arrive, with a progress card that can cancel it (up to 4 GB per zip). Uploading a file or folder whose name is taken asks Keep both (the default: "name (1).ext"), Replace (the file keeps its shares; a folder takes the new files in) or Skip, with "Do this for all" when there are more; Cancel stops the whole upload. "New text file" in the folder menu creates an empty text file (new-file.txt), saying at once when the server would refuse the name. Messages saved as .eml are now named like Bulwark's ("date (from-to) subject.eml"), and the Settings > Files > Downloads rows (spaces, lowercase, strip diacritics, collapse separators) now apply to saved messages, attachment downloads and messages forwarded as attachments; "After export" archives or deletes a message once it is saved as .eml.
- Sharing: mail folders, calendars and address books can now be shared with other people and groups on your server, as in Bulwark. Right-click a folder (Share…), a calendar (Share calendar…, also on Settings > Calendars) or an address book (Share address book, also on Settings > Contacts): the dialog lists who has access, lets you pick Read only, Read & write or Manager (and Free/busy only for a calendar) for each, add someone from the server's directory (search by name or address; a new person starts with Read only) and remove access. Folders need a server that offers folder sharing; calendars and address books show the item only when you may share them. A grant Barbican or Bulwark did not make shows as Custom and is left as it is unless you pick another level.
- Live updates and notifications: calendars and events, address books and contacts, files and your identities now follow changes made elsewhere (another device, a shared calendar's owner) within a moment, fetching only what changed; when the server cannot tell what changed, the view is loaded again in full. When someone shares a folder, calendar, address book or file folder with you, changes or removes your access, or invites you to, updates or cancels an event, Barbican says so (several changes by one person, or more than three event changes, come as one line) and the shared item appears without a reload. A bell in the rail lists removed shares and cancelled events with an unread count (Mark all read, Clear); the list stays on this computer until the last account signs out.
- Settings sync: your Barbican settings now follow your account to your other computers. They are kept in your account on the server (your Inbox's metadata, under Barbican's own name, so Bulwark's settings are not touched), pulled when you sign in or switch account and sent a few seconds after you change one. Plugins and their permissions, sign-ins, trusted senders, remote content and avatars, read receipts, the send and delete warnings and confirmations, permanent deletion, the desktop and assistant settings and this computer's window are never synced, and nothing synced from the server can change them. Changes made just before you switch account or sign out still go to that account; signing out of the last account puts the synced settings back to their defaults on this computer. Anyone you share your Inbox with can read the synced settings, and they are kept small (20 KB) to leave room in the Inbox; the row shows why the last sync failed. A change you made here that never reached the server is kept over an older copy; an account that has no copy yet starts from the default settings when another account's are on this computer. Settings > About > Settings sync turns it off; on a server without metadata the row says sync is not available.
- App lock: Settings > Password & sign-in can lock Barbican with a PIN (at least 5 characters; obvious ones such as 12345 or 111111 are refused). It locks every time Barbican starts and after a time without use in the window (1 minute to 4 hours, 10 minutes by default, or only when Barbican restarts), and "Lock now" locks at once. The lock screen covers the whole window: nothing of your mail, calendar, contacts, an open message or a draft shows or can be clicked, and notifications say only "New mail" or "Upcoming event" while it is locked; you stay signed in and mail keeps arriving. On a computer with Windows Hello you can also unlock with your face, fingerprint or Windows PIN. The PIN is never stored: only a salted, slow hash in the system's credential store (Windows Credential Manager), and after 4 wrong tries each next one waits longer (30 seconds, doubling up to an hour), also after a restart. A forgotten PIN can't be recovered: "Forgot your PIN?" signs out every account on this computer, which also removes the PIN. Signing out of the last account removes it too. There is no passkey unlock, which needs a web browser.
- The Stalwart admin API key is now kept for the server and account it was entered under, and is never sent to another one. A key saved by an earlier version is not used: enter it again in Settings.
- Out of office now matches Bulwark's: choose who gets the reply (everyone, only your own domains, or only others), forward mail while you are away (the address is saved with "Save forwarding", with an option to keep a copy in the Inbox), write the message as HTML, set start and end with a time, and block your calendar with a busy event for the dates. These settings are stored the way Bulwark stores them, so a reply set in one app shows in the other. Reply templates from an organisation library are not included yet.
- Out of office: the page no longer freezes when both dates are set, an "&" before a letter such as Ü in the HTML message no longer closes the app, and switching accounts never shows or saves the previous account's reply. A message typed just before "Block my calendar" (or before an edit that is refused) is still sent, what you typed stays on the page when a save fails, editing one date no longer moves the other by an hour on the night the clocks go back, a date alone stays an all-day block where the clocks change at midnight. A hand-written filter whose comment says "Vacation auto-reply" now survives the first out-of-office save of a script Barbican or Bulwark did not write; from the next save on it is taken for the generated auto-reply and dropped, as in Bulwark. Reopening the page while a change is being saved no longer shows (and later sends back) the reply as it was before; a forwarding address saved while forwarding is off stays in the field; forwarding or reply recipients that could not be written to the filters script stay as set and are written with the next change; emptying the HTML message no longer brings it back from the plain text; a date that is not one yet, or an end before the start, is marked at once; and a change on another settings page no longer drops an out-of-office change still waiting to be saved. When switching the reply off reaches the server but not the filters script, the page says the reply is "Still running" and offers "Try again" (it is also retried with the next change). A half-typed forwarding address no longer holds back the rest of a change, the field says when it differs from the stored address, and a reload shows the stored one. Typing a date and time is no longer rewritten while you type, and a calendar event of ours whose times cannot be read is left alone instead of being created again.
- Plugins: Settings > Add-ons can install a plugin package (a .zip file or a folder with a manifest.json and its library). The package is checked before anything is written (at most 200 files, 20 MB per file and 32 MB in all; no paths that leave the package, absolute paths, drive letters, Windows device names, links or names that differ only in case), its manifest is checked (id, version, plugin API 2, known permissions, hooks and slots that need them, https-only web origins without IP addresses), and it is unpacked into its own folder, switched off; it never replaces a file or folder that is not a package with the same id, and asks first when the new package has a different author than the one it replaces. The install runs in the background, so the window stays responsive; only one install or uninstall runs at a time, and the question before replacing a plugin opens over the main window. Switching a plugin on now shows what it asks for in plain words, the riskiest first, with the sites it may connect to and, listed apart, any hosts inside your network; your yes is pinned to the whole package (every file in it, at most 64 MB), read again from disk right before the dialog and before the plugin is loaded, so an updated plugin is off until you accept it again. For an update by the same author the dialog names the old and new version and says it asks for the same permissions as before, or lists everything it asks for and marks what is new; a package by another author (or one Barbican cannot tell, for example when a package names no author) takes nothing over and is asked about as a new plugin, and installing it over the old one asks first and forgets what you had accepted. An id that a plugin dropped into the plugins folder already uses cannot be installed, and uninstalling a package forgets only its own grant. An update that stops halfway keeps the installed version, and the next start puts it back if needed; uninstalling also removes the plugin's update backups. A package whose name or other text holds control, direction or zero-width characters is refused (the joiners Persian, Indic and emoji text needs are fine); errors from a plugin are shown cleaned and cut to a readable length. Anything else written into a plugin's folder changes it too (plugins keep their data in plugin-data), and a plugin folder that is a link or junction is not listed. Installed plugins have an Uninstall button that removes the plugin and the data it stored. API 2 plugins are recorded but not run yet. API 1 plugins (a .dll dropped into the plugins folder) keep working; switching one on shows the same dialog with the hooks it uses, and one you had already switched on stays on.
- Settings > Password & sign-in now manages your Stalwart account's security (the page shows only on an account whose server offers it): change the password (the app signs in with the new one at once, and updates the remembered sign-in if you chose to remember it), turn two-step sign-in on (a secret key and setup link to type or copy into an authenticator app, checked with a code before it is switched on) and off, and create and delete app passwords. With "Show advanced settings" it also lists API keys and, for encryption at rest, public keys with the option to turn encryption on with a key (AES-128 or AES-256) or off. A new app password or API key is shown once, with a Copy button that keeps it out of Windows' clipboard history; nothing you type here is saved or logged, and it is all forgotten when you close Settings, sign out or switch account. Deleting, turning encryption on and the like ask you to press twice (not within a double click), and turning encryption on says that Barbican cannot show encrypted mail and that the private key is needed. A password change updates the session and the remembered sign-in only when they used the password you typed (an app password session keeps working; a session with a two-step code signs you out and asks you to sign in again with the new password), and turning two-step sign-in on clears the remembered password when it is the one you typed (the account stays in the account list; starting or switching to it then says why it cannot sign in, and signing in on the form with a password that works without a code, such as an app password, puts it back). There is no QR code yet: use the secret key or the link.
- Folders: the folder menu (right-click a folder) now has Pin to top, Mute notifications (not for Trash, Spam, Sent or Drafts), Subscribe / Unsubscribe, Counter (default, unread only, unread and total, none), Icon (the same 18 icons as Bulwark), Use as standard folder (Inbox, Drafts, Sent, Trash, Spam, Archive: one folder per role, the old holder loses it first, and moving the Inbox, Sent or Drafts role asks first) and, for a folder with unread mail in its subfolders, "Mark folder and subfolders as read" (batched to your server's limit; a failure part-way keeps what was already marked). Icons, counters and mutes are kept under Bulwark's own setting names (`folderIcons`, `folderCountModes`, `notificationMutes`), so a settings export moves between the apps. Pins and subscriptions are Barbican's own: Bulwark has no folder pin and no subscribe control (it lists every folder and shows nothing for that state), so pins are kept per account in `pinnedFolders` and sort first among their sibling folders, and an unsubscribed folder is listed with its name dimmed. New-mail notifications stay quiet for a muted folder (mail also filed in an unmuted folder still notifies) and for Archive. Pins, mutes and icons are kept on this computer, not on the server, and custom icons show in the Bento theme only (the other themes list folders without icons).
- Templates: Settings > Composing can now edit an existing template (name, category, subject, body, default To/Cc/Bcc, favourite) and make its body rich text (HTML, cleaned by the same sanitiser as incoming mail). Inserting a template that has {{placeholders}} opens a dialog first, pre-filled with today's date, your name and any {{name:default}} defaults, with an "Insert as written" choice; the composer's Templates menu also has "Save as template..." for the current draft. Templates are stored exactly as Bulwark stores them (your Inbox's metadata, one entry per template, 8 KB at most each), so both apps see the same ones; a server without metadata keeps showing none.
- Templates: editing a template no longer flattens its rich body or overwrites a newer change made in Bulwark, inserting one into a reply or forward keeps the recipients, and the HTML switch converts the body.
- Identities: Settings > Account > Your addresses can now add an address (the server decides which ones you may send from), edit one (name, Reply-to, Bcc, signature) and delete one. The primary address and one the server does not mark as deletable cannot be deleted, and a delete asks first. Settings > Composing > Signatures opens the same form. Changes are saved with Save, not while you type, and half-typed input is not thrown away by one click. While a save or delete is on its way the form is read-only and a second click does nothing, so a double click cannot add an address twice. Editing only the name, Reply-to or Bcc leaves the signature exactly as stored. A save made after you switched accounts is refused, so nothing is saved in the wrong account.
- Identities: Bcc adds a blind copy to every message sent from that address. It goes out with the send only, as an extra recipient of the submission rather than a line in the message. So no draft gets it: not a saved draft, not the draft an undone send brings back, and not one whose sending failed. Your Sent copy does not list it under Bcc, and it is not added twice when the person is already a recipient.
- Signatures: a signature can be formatted (HTML: bold, links, a picture by web address). Barbican edits the HTML source, removes scripts and the like with the same sanitiser as incoming mail when you save, keeps a plain-text copy next to it, and refuses an edited signature over 2047 bytes, which is Stalwart's limit. The size is measured as the signature would be saved, and the sanitiser's formatting adds some size; a signature you leave unchanged is not sent or measured again. It shows the size from 90% of the limit. With Composing > Plain text only, the signature is edited as text and a formatted version is left as it is. There is no WYSIWYG signature editor, and Bulwark's "Your details" (`signatureDetails`) is not offered: it only fills in organisation signatures set by an admin, which Barbican does not have.
- Identities: "Set as primary" picks the default sender. It goes first in the composer's From list and in Settings. Otherwise your login's own address comes first, ahead of a group address the server lists before it. The choice is kept per account under Bulwark's key and format (`preferredIdentityIds`), so a settings export carries it.
- Masked addresses: Settings > Password & sign-in lists your masked addresses (Stalwart `x:MaskedEmail`), ten to a page, on servers that have them. You can copy one, edit its description, turn it off or on, delete it permanently (it asks first), create one for a website, and refresh the list. On servers without them, Stalwart Community among them, the section stays hidden. Every answer is checked: it must be for your account, the list must be read in full, and a delete only counts when the server confirms it. A delete that cannot be confirmed is not retried.
- Composer: "Use a sub-address…" in the From menu sends from `you+tag@domain`, using the sub-address delimiter set in Settings > Account. It shows a preview, your recent tags and suggestions for the recipients' domains, and "Remove tag" goes back to the plain address. Only the From header changes: the message still goes through the identity.
- Templates: signing out closes an open "fill in the template" or "Save as template" dialog (they stayed over the sign-in page) and forgets the account's templates and what was typed into them.

## 0.2.1 — 2026-11-24

- Updates through Hub or the installer now close a Barbican that is running in the tray (it saves an open draft first) instead of stopping with "Setup could not close Barbican". The update to this version still needs Barbican to be quit by hand once (tray icon, Quit), because the older version does not listen for the signal.

## 0.2.0 — 2026-11-24

- Plugins: API v2 decisions recorded in PLUGINS.md (for plugin authors, nothing changes in the app yet): web access to a private, loopback or LAN host needs that exact host named in the manifest and the user's separate consent (https only, never a wildcard); API 1 plugins keep loading until 1.0; a slow pre-send check shows a pending state and can be cancelled without skipping it; Barbican's own host calls, `crypto:full` and the package layout are kept, phone-layout hooks and WebAuthn stay out.
- Settings > Message list > Deleting & archiving has "Trash retention (days)" and "Junk retention (days)" (0 or empty hides the note, at most 3650). They set the line shown under the title of Trash and Junk, which updates at once when you change a value; your server's retention policy still decides what is really deleted.
- Mail: a winmail.dat's own message text now shows in the reader when the message has no real HTML body (Outlook's empty Word boilerplate counts as none): the HTML goes through the same sanitiser and remote-content rules as any message, plain text is shown as text, and a message that has a real body keeps it.
- Mail: "Import .mbox files as subfolders..." in the folder menu imports each picked .mbox / .mbx into its own subfolder of that folder, named from the file (without the extension, "Imported" when empty), reusing a subfolder of that name if there is one and making it otherwise. An .eml file goes into the folder itself. Messages already in a folder are still skipped and every import keeps the `$imported` keyword.
- Mail: "Export all mail as .mbox files..." and "Export all mail as .eml files..." in the folder menu write every folder of the account into a new "Mail export <date>" folder you choose the place for: one `<folder>.mbox` per folder with messages (or one subfolder of .eml files per folder, empty folders kept), nested as the folders are, names made safe for the file system, twins numbered "(2)". Progress counts over the whole account, "Cancel export" stops it and removes the new folder.
- Reader safety: "Report phishing..." is now also in the message list's right-click menu (next to "Report spam") and in the selection bar, for one or several selected messages. It asks once, naming the address from Settings, then sends one report per message and moves each to Junk (read, with `$junk` and `$phishing`). The toast has an Undo that moves the messages back to the folder they were in and clears the junk and phishing marks (the reports already sent are not recalled). A message in a shared account is not reported, and the app now says so instead of doing nothing; sent, draft and already reported messages are left out and counted.
- Mail: drag messages onto a folder of another signed-in account to move them there. While you drag, the other connected accounts' folders appear under the folder list; each message is copied first and removed from the source only once the copy exists (never by the server's "destroy original on success"), the toast says "Moved to ..." or "N emails moved to ...", or the first error, and the folder counts of both accounts are refreshed.
- Copy to another account: the menu lists only accounts that are connected, loads each account's folders once at a time and says "Could not load folders" (instead of "Loading folders..." forever) when that fails, forgets an account's folders when its folder list changes, and refreshes the destination account's folders and counts after a copy.
- Attachments: renaming an attachment in the composer refuses text direction characters (including the Arabic letter mark), saved names drop them too, CONIN$, CONOUT$ and COM or LPT followed by a superscript 1, 2 or 3 count as Windows device names, and a saved name is cut to 255 bytes (not characters) keeping its extension; an absurdly long extension is cut as well.
- Calendar invitations: a counter proposal for one occurrence of a recurring meeting (another time, place, title or description) can now be applied from the banner, which lists its changes. It gives that occurrence its own entry in the series (or changes the one it has) and leaves the other occurrences and the series itself alone; attendees hear of it, and those who had answered are asked to answer again when the time moves. Times in another zone or UTC are read as the same moment in the meeting's zone. A proposal for an occurrence the series excludes or does not have is not offered. The banner now also shows when a proposal removes the place or the meeting link ("Location: X → (none)"), and a proposal for a whole meeting given without a time zone, or in UTC, is read in the meeting's own zone instead of making the meeting floating.
- Trusted senders are kept in your server's "Trusted Senders" address book, the same book Bulwark uses, so both apps share the list (Settings > Privacy > "Sync with address book", on by default). "Trust sender" adds a card with the sender's address; removing a line in Settings > Privacy > Trusted senders (then "Save changes") removes it again. Addresses already on this computer's list are filed into the book the first time and then leave this computer's list; one that cannot be filed stays on it. The book is read in the background at sign-in and when the server says contacts changed, and a sender counts as trusted when this computer's list or the book holds it. With the setting off, or on an account that cannot keep address books, the list stays on this computer only and Barbican does not touch the server; turning it off keeps the book's senders trusted here. Barbican creates the book only when it has something to put in it, never merges or deletes duplicate books, and removes only a card it could have written itself (a card filed elsewhere, or with other addresses or data, is only unfiled or loses that one address). Signing out leaves the book on the server. This computer's list is filed into a book only when exactly one account is remembered here; when you turn the setting off, each address copied from a book is remembered as belonging to that account and is never filed into another account's book. "Save changes" compares your edit with the list as it was shown, so an address that joined meanwhile is never removed, and an edit made for another account or before a sign-out is dropped; removals wait until the book has been read. A card that cannot be filed is not retried on every update. An old Bulwark settings file with the setting off that did not record it as chosen turns it on when imported.
- Reader safety: "Report phishing" in the message's More menu sends the message to the address set under Settings, Privacy & security (forwarded as an attachment or as an abuse report), moves it to Junk and marks it `$phishing`. A message marked `$phishing` shows a warning and has its links turned off. The verified brand badge (BIMI mark certificate) appears next to the sender when the sender's DMARC policy is enforced and a valid certificate backs the logo. Authentication results are trusted only when your own server wrote them: a forged Authentication-Results header from the sender no longer opens one-click unsubscribe, the invitation trust checks or the brand logo.
- Mail: a folder can be exported (right-click the folder, "Export folder as .mbox..." or "Export folder as .eml files..."). The mbox keeps read, answered, flagged and draft state and keywords in the headers the import reads back, and quotes "From " lines (mboxrd); the .eml export writes numbered files with safe names (no path separators, no Windows device names, at most 60 characters of subject) into a new folder. One message is held in memory at a time, the toast shows progress, "Cancel export" in the folder menu stops it and removes the partial file, and a message that cannot be downloaded is counted and skipped.
- Mail: a winmail.dat (application/ms-tnef) attachment up to 5 MiB is decoded and the files inside are listed as normal attachments (open, save, download all); the winmail.dat itself is hidden once it yielded files. The decoder checks every length and count, so a damaged or hostile file gives what could be read, never a crash.
- Plugins (for plugin authors, nothing changes in the app yet): PLUGINS.md describes the planned plugin API v2, with native plugins that exchange JSON messages with Barbican, a manifest with permissions and allowed web addresses, a consent dialog, per-account storage, and plugin panels described as data that Barbican draws itself. Each of Bulwark's 218 hooks, 58 panels and 186 host calls is marked as taken over, changed or left out (spec/plugins), so a Bulwark plugin can be ported by hand.
- Copy to another account: with more than one account signed in, "Copy to account" in the message menu and in the reader's menu lists the other accounts and their folders. Within one login the server copies the message (Email/copy, keywords kept); between two logins the raw message is downloaded and imported into the other account (keywords and arrival time kept). Each message is copied on its own, a failure is reported with the first reason while the others still go through, and nothing is ever removed from the source.
- Rename an attachment: right-click a chip in the composer (Rename / Remove) or an attachment in the reader (Rename...). Only the part before the extension is edited, so the file keeps its type; the new name goes out with the message, or names the saved copy. Saved files get safe names (no slashes or control characters, no direction overrides, no Windows device names, at most 255 characters).
- Trash and Junk show a quiet line under the title, "Messages here are deleted N days after they were moved here", when the server's retention is known. Barbican has no admin policy file, so you enter the days in Settings > Message list (0 shows nothing).
- Reader safety: remote content is now decided per sender, with Bulwark's settings (`externalContentPolicy` ask / block / allow and `trustedSenders`, the same keys, so a settings export moves between the apps). Settings > Privacy has "Remote content" (Ask first, Always block, Always load) and a "Trusted senders" list (one address per line). The banner for blocked images offers "Load images" (only under Ask) and "Trust sender" (not for a sender whose authentication failed); a trusted sender's images always load, also under Always block. Your old "Load remote images" choice is kept until you pick one. Trust is per address, as in Bulwark. Signing out the last account removes the trusted senders from this computer; your other preferences stay.
- Messages from outside your own domains (the domains of your identities, subdomains included) show an "External" label in the reader; a From address with no domain counts as outside. Settings > Privacy > "Label external senders" turns it off. Settings > Privacy > "Confirm before sending outside" (off by default) asks before sending to anyone outside your domains and lists them, in the same warning as the empty-subject and plugin checks (a scheduled send says "Choose Schedule send again...").
- Upgrading from 0.1.0 with SSO no longer asks you to sign in again on a later start; a failed automatic sign-in now says why and retries network errors. A restored sign-in never writes back an older token than the one it just used, a 0.1.0 entry and the new one for the same login become one account, and a token the server rotates while the saved sign-in is restored is stored at once. When the saved sign-in is turned down, the message names the account (or the server) and says that the saved entry stays until you sign in; when the server cannot be reached, Barbican keeps "Signing in…" and tries again (after 2, 5, 15 and 30 seconds), then shows the form with the reason and a "Try again" button. Each retry starts from the sign-in token the store holds then, so a refresh that worked and was followed by a network error no longer leaves the retry with a token the server already replaced. "Try again" does not bring back a sign-in that was signed out in another window. A saved sign-in that cannot be read says so instead of showing an unexplained form.
- Filter rules: "Reject with message" is offered only when the server lists the reject Sieve extension. A rule that already rejects still shows its action, with a note, and is saved as it was.
- Calendar: the all-day strip above the day and week grid is capped at three rows, as in Bulwark. A day with more all-day items shows two and a "+N more" row; that row, or the "+N" button beside "All day", expands the strip to every row, and the button then collapses it again. The strip is 28 px tall at least and 24 px per row (Bulwark's numbers).
- Long messages open whole: when the server cuts a long message body, Barbican fetches it again at once with a larger limit (8 MB instead of 2 MB), as Bulwark does, and the notice only appears when that failed or the message is longer still. "Load full message" in the notice fetches again; before, it asked for no limit, which the JMAP standard does not allow, and it did not update the copy kept for reopening the message. The text is shown through the same safe reader (sanitised HTML, remote images off unless you allowed them). A message longer than 8 MB says so and points to View source and Save .eml.
- Settings > Account shows your storage: "Storage usage" with how much is used of the limit, the percentage and a bar (the soft limit counts as the limit when the server sets one, as in Bulwark). When the server reports several quotas (message counts, other data), each gets its own line. The quota is also found when the server names its type Email.
- Reminders: an event's own reminder set far ahead (for example "2 weeks before" on an event a month away, or a reminder at a fixed date and time) now fires. Before, only events starting within about 8 days (or as far as the calendar's default reminder reaches) were watched, so such a reminder was missed. Barbican now also looks at later events that carry an early reminder, once at start, every half hour and when a calendar changes, without reading the whole calendar every few minutes. A shared calendar that cannot be read no longer hides your own far reminders or makes Barbican scan again every few minutes. Reminders that were already shown or listed as missed stay acknowledged.
- Re-opening a saved draft that holds inline pictures now ties every picture to its own part by Content-ID, as Bulwark does, instead of by position: before, a draft whose pictures were stored in another order than they appear in the text could show them swapped, and a picture pasted as plain data could be given another picture's identity. Sending the draft again keeps each picture's cid and attachment, and real attachments stay attachments. A reply or forward draft keeps the pictures of its quoted original when it is saved or sent again, instead of dropping them and leaving broken images.
- Importing a .ics file asks what to do with the reminders that are in it: when some events carry their own reminders, the import dialog shows "Keep the reminders from the file", switched on (as in Bulwark, which always keeps them), and switching it off imports those events without reminders (also for single occurrences of a series). Files without reminders show no question.
- Calendar subscriptions (webcal://) no longer fetch from this computer or your own network: addresses like localhost, 127.0.0.1, 192.168.x.x, 10.x.x.x, 172.16-31.x.x, 169.254.x.x (including the cloud metadata address), fe80::/fc00::/::1 and 0.0.0.0, written in any form (2130706433, 0x7f000001, 0177.0.0.1, 127.1, IPv6 with an IPv4 address inside), and names such as localhost, *.local or *.internal, are refused with a message. A name is looked up once, every address it gives must be public, and the connection goes to those very addresses; every redirect (at most 5) is checked the same way, and a login in the address is only sent to the address it was typed for. A system proxy is not used for feeds. An unencrypted http:// address is still accepted, with a warning under the address field and in the message after subscribing.
- Calendar invitations: a counter proposal an attendee sends for an event you organise now shows what it changes (time, place, title, description) in the invitation banner, and "Apply proposed changes" updates the event and sends the update to the attendees, asking those who had answered to answer again when the time moves (as Bulwark does). It is offered only for a proposal from one of the event's participants. There is no button to decline a proposal, as in Bulwark: the server has no way to send a decline, so ignoring the message declines it. A proposal for a single occurrence of a recurring meeting is not applied yet (the banner lists no changes); only a proposal for the whole event or for an occurrence stored on its own is.
- Calendar invitations: a cancellation of an event is now offered as "Remove from calendar" in the banner when the message is verified as the organiser's and the stored event is theirs (a whole series is deleted, one cancelled occurrence is excluded from its series); one older than your copy, or from someone other than the organiser, says so and removes nothing. If the event is deleted elsewhere after you opened the message, the Remove button goes away.
- Contacts: saving a contact no longer loses the other units of its organisation. Editing the Department field changes only the first unit of the first organisation; its other units, the other organisations and properties Barbican does not show are kept, and emptying the field removes only that first unit.
- Contacts: a birthday on 29 February now counts down to 1 March in years that have no 29 February (it used to point at a date in the past), and a date typed in the contact form must be a real calendar day (31 April and 29 February 2023 are refused; 29 February without a year is fine).
- Contacts: importing a vCard file from someone else is bounded. A file over 16 million characters is refused (a file above 64 MB is not even read; a smaller one is read, then refused), at most 10 000 contacts are read per import, a line over 1 million characters is skipped, a card keeps at most 5 000 property lines, 500 entries of each kind, 500 units in an organisation and 500 types on a line (a line repeating TYPE or WORK a hundred thousand times no longer freezes the import), a card begun inside another card starts the card over, and a photo above 8 MiB or whose text is not base64 is left out while its contact is kept. The import summary says what was left out.
- Contacts: a picked or stored picture above 8 MiB, or above 40 million pixels by the size in its header, is refused before it is decoded, so a small file that claims a giant picture cannot make Barbican use gigabytes of memory.
- Contacts: an exported vCard can no longer carry a line break inside a value (addresses, numbers and links were written as they were), so a contact cannot forge extra properties or end its own card in an export. Media types in exports are checked, and the file name offered for one exported contact never ends in a dot, is never a Windows device name and is at most 80 characters.

## 0.1.1 — 2026-11-24

- The window reopens where you left it: its size, position and whether it was maximised are remembered on this computer (not synced with your settings). When the monitor it was on is gone or the screen changed so the window would be off screen, Barbican opens at the default size and place instead.
- Sign-in safety: redirects from the server are followed by hand, to the same address only and never from https to http, at most 5 hops (session discovery, API calls, downloads, uploads, push, the admin key and the AI key). A server that redirects elsewhere is refused with the address named instead of ending in "wrong password". A sign-in the server turns down is tried once: no reconnect loop, no refresh loop, and you are told once. Two Barbican windows on one profile no longer lose a rotated sign-in token, and closing one no longer writes its older copy over a newer one.
- Credentials: secrets are kept per profile (`BARBICAN_PROFILE`; the default profile is yours), in the Windows Credential Manager with local-machine persistence (not roaming). Your 0.1.0 sign-in moves over by itself the first time 0.1.1 starts; going back to 0.1.0 afterwards asks you to sign in again. Test and automation runs (`BARBICAN_AUTOMATION=1`) never use your profile: without a profile they get `auto-<port>`, with their own folder and sign-in.
- Clicking a new-mail notification now shows the folder the message is in, not only the message: the folder is selected in the list on the left (and unfolded when it sits inside a collapsed folder), its messages are listed and the message is highlighted. Before, the folder that was open before stayed selected, so the message and the folder disagreed. A message that was filed to another folder since the notification is found where it is now, a deleted one only says it is gone, a search or tag is cleared so the message is in the list, and the "All inboxes" view gives way to the message's own folder (as Bulwark does). Notifications for several new messages select the Inbox of the account that got them the same way. A notification of another signed-in account switches to that account first (as Bulwark does) and then opens the message in its folder (or the Inbox); accounts are matched by the login you signed in with, also when the server's own name for the account differs from it. If you open another folder or message while the message is being looked up on the server, you stay where you are. A search that already lists the message is kept. The Archive, Mark as read and Delete buttons on a notification of another account now say that it belongs to another account instead of doing nothing.
- Fixed: switching on Gravatar photos (or sender favicons) crashed Barbican at once, and then on every start. If a start does crash, the next one runs with sender pictures off and says so.
- Signing out removes the account's data from this computer: its caches, trusted senders, the mail view's cookies and storage, plugin data and the saved sign-in. Files that are still in use are removed at the next start.
- Signing out is per profile: a profile keeps its own mail view data, files opened from mail and print file (`%TEMP%\Barbican-<profile>`, the default profile keeps `%TEMP%\Barbican`), so signing out in one profile never deletes another profile's data. The login form no longer keeps the password or 2FA code after signing in or out, and a sign-out says so when the saved sign-in could not be removed from the Credential Manager. A start that crashed is only noticed when the first list did not get drawn (not after a fixed 8 seconds), and a second Barbican window is no longer put into safe mode by the first one starting, nor does closing it clear the first one's check. Only the default profile checks for and installs updates.

## 0.1.0 — 2026-11-23

- First installable build: a per-user Windows installer (Inno Setup, Barbican-Setup-<version>.exe), next to the portable zip, with a Start menu shortcut, an optional desktop shortcut and upgrade in place. It needs no administrator rights, and it never ends a running Barbican (including one only in the tray): it asks it to close, waits up to 30 seconds, and when it is still there it asks you to close Barbican first instead of installing, so an open draft is not lost. Uninstalling also removes the registry entries the app wrote for itself (start at login, the mailto: registration).
- barbican.exe carries a Windows version resource and the application icon, so Explorer and Hub show the right version.
- Updates: an install made with the new installer can update itself like the MSI one does (signed manifest, SHA-256 check, installed only when you say so).
- Mail, calendar and contacts in the Bento × Nordic design, with a native rich-text composer (spelling, tables, images), a unified inbox, schedule send, invitations, filters and Sieve extras, a command palette and search, drag and drop, and .eml/.mbox import.
- Settings include an accessibility page; the app can start in the tray, close to the tray and show an unread badge.
